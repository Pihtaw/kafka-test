# KafkaReplay — проверка и перенос событий Kafka

Утилита читает топик за **промежуток времени** (не по номерам), проверяет каждую запись через MessageCheck и пишет отчёт. Сейчас работает только dry-run: **ничего не отправляет**.

```
топик -> [1] время -> offsets по каждой партиции, Assign без коммита
      -> [2] заголовки списком байтов -> MessageCheck -> решение + причина
      -> [3] сводка + проверка сходимости
      -> [4] <папка запуска>/report.json
```

## Структура

```
KafkaReplay/
  src/KafkaReplay/       — утилита (собирается в программу replay)
  tests/KafkaReplay.Tests/ — тесты параметров, подключений, контрольных сумм
MessageCheck/            — проверка одной записи: заголовки → каталог → JSON → решение
Seeder/                  — наполняет топик тестовыми событиями
learning/                — учебное
docker-compose.yml       — локальная Kafka и интерфейсы для неё
```

## Запуск

```bash
docker compose up -d

# 1. Наполнить топик orders-multi: наши, чужие и битые события
cd Seeder
dotnet run
# в конце Seeder печатает готовую команду для шага 2 с нужным временем

# 2. Проверить их (команду скопировать из вывода Seeder)
cd ../KafkaReplay/src/KafkaReplay
dotnet run -- --bootstrap localhost:9092 --topic orders-multi \
  --from "2026-10-14 15:00:00+03:00" --to "2026-10-14 15:05:00+03:00"
```

Параметры:

| Параметр | Что это |
|---|---|
| `--topic` | топик-источник |
| `--from`, `--to` | окно по времени, формат `yyyy-MM-dd HH:mm:sszzz`, часовой пояс обязателен |
| `--bootstrap` | локальная Kafka без пароля, например `localhost:9092` |
| `--source-env` | или имя переменной окружения со строкой подключения (см. ниже) |
| `--out` | папка для отчёта, по умолчанию `run-<дата>-<время>` |

Нужно указать ровно одно: `--bootstrap` или `--source-env`.

## Подключение к кластеру

Для локальной Kafka достаточно `--bootstrap localhost:9092`.

Для настоящих кластеров утилита понимает **строку подключения в том же формате, что Dodo.Kafka** (так подключаются сервисы):

| Кластер | Строка подключения |
|---|---|
| dev-стенд | `BootstrapServers=kafka.stand-name:9092;` |
| Azure Event Hubs (SAS) | `BootstrapServers=ns.servicebus.windows.net:9093;Type=EventHubSas;SharedAccessKeyName=...;SharedAccessKey=...;` |
| Yandex Managed Kafka | `BootstrapServers=c-id.mdb.yandexcloud.net:9091;Type=Yandex;Username=...;Password=...;` |

Строка целиком — секрет, поэтому её нельзя передать параметром: она попала бы в историю команд. Утилита берёт её из переменной окружения, а в параметре указывается только имя переменной:

```bash
export REPLAY_SOURCE='BootstrapServers=...;Type=EventHubSas;SharedAccessKeyName=...;SharedAccessKey=...;'
dotnet run -- --source-env REPLAY_SOURCE --topic orders \
  --from "2026-10-14 15:00:00+03:00" --to "2026-10-14 16:00:00+03:00"
```

Настройки подключения такие же, как у kafka-tools: keepalive и обновление метаданных раз в 3 минуты (Azure закрывает простаивающие соединения), для Yandex — SCRAM-SHA-512 без проверки сертификата. Ошибки в строке подключения называют только имя поля, значения никогда не печатаются.

`Type=EventHubAd` (вход через Azure AD) пока не поддерживается: в kafka-tools токен для него берётся через `DefaultAzureCredential`, добавить.

Event Hubs и Yandex проверены тестами на уровне настроек; на настоящем кластере ещё не запускались.

## Что должно получиться на данных Seeder

15 сообщений:

| Решение | Сколько | Какие |
|---|---|---|
| Allowed | 5 | OrderCreated 1.0.0 (два, у одного лишнее поле Comment), OrderCreated 1.1.0, OrderCancelled, OrderCreated 2.0.0 |
| Skipped | 3 | чужие PaymentCaptured и CourierAssigned, tombstone |
| Rejected | 5 | нет Event-Type, пустой Event-Type, не UTF-8, Event-Type дважды (разные и одинаковые) |
| ConversionError | 2 | оборванный JSON, пустое тело |

В конце: `Дочитаны партиции: 3 из 3`, `Сводка сходится` и `Код выхода 1` — на этих данных есть отклонённые записи, так и задумано.

## Коды выхода

| Код | Когда |
|---|---|
| 0 | всё прочитано, сводка сходится, отказов нет |
| 1 | отработала, но есть записи, отклонённые проверкой (Rejected или ConversionError) |
| 2 | диапазон дочитан не полностью или сводка не сходится |
| 3 | не запустилась: неверные параметры, ошибка в строке подключения, нет переменной окружения, нет связи с Kafka |

## Что в отчёте (report.json)

- `source` — тип и адрес подключения, без секретов;
- `partitions` — план чтения по партициям: low, high, [start; end), зафиксированный до чтения;
- `summary` — прочитано и запланировано, разбивка по решениям, причинам и типам событий, флаги `allRead` и `sumMatches`;
- `exitCode` — код выхода;
- `records` — по каждой записи: партиция, offset, время (и `outsideWindow`, если время записи вне окна), ключ, заголовки (текст и hex исходных байтов), тело, решение, причина, JSON после DTO и две контрольные суммы:
  - `payloadSha256` — только тело события;
  - `recordSha256` — ключ, заголовки и тело;
