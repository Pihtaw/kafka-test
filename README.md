# DryRun — демо версия всего пайплайна

Читает топик за **промежуток времени**(не по номерам), проверяет каждую запись через MessageCheck и пишет отчёт в один файл(**не отправляем**).

```
топик -> [1] время -> offsets по каждой партиции, Assign без коммита
      -> [2] заголовки списком байтов -> MessageCheck -> решение + причина
      -> [3] сводка + проверка сходимости
      -> [4] report.json
```

## Запуск

`docker compose up -d`

```bash
# 1. Наполнить мультитопик orders-multi (наши, чужие и битые события)
cd Seeder
dotnet run
# удобно в конце печатаем время для проверки сразу

# 2. Dry-run по этому промежутку
cd ../DryRun
dotnet run -- orders-multi "2026-10-05 18:00:00" "2026-10-05 18:05:00"
```

## Что должно получиться на этих данных?

| Решение | Сколько | Какие |
|---|---|---|
| Allowed | 5 | 4 валидных события + eventType дважды с одинаковым значением |
| Skipped | 2 | чужие: PaymentCaptured, CourierAssigned (без version) |
| Rejected | 5 | неизвестная версия, нет eventType, пустой eventType, не UTF-8, eventType **дважды с разными значениями** |
| ConversionError | 1 | оборванный JSON |

В конце: `Прочитано 13 из 13` и `✅ Сводка сходится`. Код выхода 0, если сходится, 2 если не сходится

## Что в отчёте (report.json)

- `partitions` — план чтения по партициям: low, high, [start; end), зафиксированный до чтения;
- `summary` — прочитано / запланировано, разбивка по решениям, причинам и типам событий, флаги `allRead` и `sumMatches`;
- `records` — по каждой записи: партиция, offset, время (+ `outsideWindow`, если CreateTime выпал из окна),
  ключ, заголовки (текст + hex исходных байтов), тело, `sha256` от исходных байтов (ключ + заголовки + тело),
  решение, причина, JSON после DTO.

Отличия «исходник ↔ JSON после DTO» и сама отправка (`--execute`) — следующие шаги.

3. `--execute`. Отправлять разрешенные сообщения в целевой топик и проставлять статусы: записано, не записано, неизвестно
